## 3. What Was Broken

1. **No `/api/health` HTTP endpoint** — only `.bat` health check existed.
2. **meta.json missing 8+ fields** — script text, voice name, audio duration, raw file path, caption timing path, fallbackUsed, errors, selectedVoice were absent.
3. **captionTiming.json not saved per render** — timing existed in memory but was never written to the output folder, so render folders were not self-contained.
4. **`package.json` missing scripts** — `typecheck`, `setup:storage`, and `healthcheck` were absent.
5. **TypeScript error** — `clearFishCudaLockout` false-positive TS6133 (pre-existing; resolved by re-running tsc after server.ts was fully restored).

---

## 4. What Was Fixed

### 4a. `GET /api/health` added to server.ts
- Added ~130-line endpoint before the `app.listen` section.
- Checks: storage folders, FFmpeg binary, Piper TTS, Fish Speech bridge, Edge TTS module, Remotion module, environment variables, output folder writability, active render count.
- Returns JSON: `{ status, version, timestamp, port, components }` where each component has `status: 'ok'|'warning'|'failed'` and a `message`.

### 4b. meta.json expanded in `scripts/trend-vault-render.ts`
Added these fields to every render's `meta.json`:
- `script` — full reconstructed script text
- `scriptLines` — array of `{ text, type }` objects
- `selectedVoice` — most specific voice identifier (name → fishVoice → elevenLabsVoiceId → presetId → engine)
- `selectedVoicePreset` — preset ID
- `audioRawFile` — raw TTS output path (if set)
- `audioProcessedFile` — post-processed audio path
- `audioDuration` — probed from processed file via ffprobe (seconds)
- `captionTimingFile` — filename of the timing JSON in the same folder
- `musicVolume`, `captionBgStyle`, `captionRotate` — previously missing visual settings
- `fallbackUsed` — boolean
- `errors` — empty array (reserved for future error capture)

### 4c. `captionTiming.json` written per render
Each `trend-vault-output/<folder>/` now also contains `captionTiming.json` with:
- `fps`, `durationInFrames`, `captionSyncMethod`, `generatedAt`
- Per-line: `index`, `text`, `type`, `startFrame`, `endFrame`, `startTimeMs`, `endTimeMs`
- Per-word (if AssemblyAI alignment was used): same fields

### 4d. New npm scripts
- `typecheck` — `tsc --noEmit` (fast type-check without build)
- `setup:storage` — runs `scripts/setup-storage.js` (creates all required folders)
- `healthcheck` — runs `scripts/healthcheck.js` (calls `/api/health` and prints readable table)

### 4e. Two helper scripts written
- `scripts/setup-storage.js` — creates 13 folders needed by Trend Vault Program
- `scripts/healthcheck.js` — CLI health reporter, exit code 1 on failure

## 8. What To Do Next

### High priority
1. **Remote render worker (port 4000)** — The biggest architectural gap. Create `render-worker.ts` as a standalone Express server that accepts job POST requests and runs `trend-vault-render.ts` in a child process. Set `RENDER_WORKER_URL=http://localhost:4000` (or remote IP). The dashboard already sends `POST /api/trend-vault/render` — that route can be made to proxy to the worker when `RENDER_WORKER_URL` is set.

2. **Audio raw file tracking** — `audioRawFile` field in meta.json is always `null` because the server does not currently pass the raw TTS output path through to the render job. Wire `audioRawFile` through the TTS pipeline output in the `/api/trend-vault/generate-voice` handler.

### Medium priority
3. **`npm run setup:storage`** — Run once on fresh installs to ensure all folders exist before first use. Add to onboarding instructions.

4. **`GET /api/health` in the Trend Vault Studio dashboard** — Add a small status indicator in `frontend/trend-vault.html` that calls `/api/health` on load and shows a warning banner if any component returns `failed`.

5. **Error capture in meta.json** — The `errors: []` field is reserved. Wire render errors from the SSE pipeline into it so completed-with-error renders have a record.

### Low priority (recommended next phase)
6. **Smaller MP4 output** — Consider adding `libx265` (HEVC) as an optional codec for ultra quality. x265 at CRF 24 beats x264 at CRF 19 in file size with comparable quality. TikTok accepts HEVC.
7. **Caption confidence** — If AssemblyAI returns confidence scores per word, include them in `captionTiming.json` for quality monitoring.
8. **Preview readiness state** — Add a UI warning in the studio if captions are stale (audio regenerated but captions not re-aligned).
