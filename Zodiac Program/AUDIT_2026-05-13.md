### Phase 5 — Cache / storage
Folders currently created automatically on server boot:
`uploads/`, `output/final/`, `backgrounds/`, `music/`, `custom-audio/`,
`zodiac-output/`, `data/drafts/`.

Folders **not** matching the brief's layout (`/storage/jobs`, `/storage/cache/*`,
`/storage/renders`, `/storage/audio/raw`, `/storage/audio/processed`, etc.):
the project uses a flatter layout under the project root. This is a stylistic
gap, not a defect. The current layout is documented and consistent. Migrating
to the brief's layout would require updating every static-file mount and every
path constant in `server.ts` — large surface area, not safe unsupervised.

Storage paths are hard-coded relative to project root rather than env-driven.
Brief recommends env-based paths.

### Phase 6 — Video render quality
- Composition is 1080×1920 vertical (confirmed by `meta.json` sample).
- FPS is currently **30** (set in `remotion.config.ts` defaults + the rendered
  `meta.json`). The brief asks for 60 fps preferred with 30 fps fallback. The
  Remotion config does not pin a frame rate in `remotion.config.ts`; the
  fps is set on the composition level. A 60 fps option would just be a
  composition-level setting + duration math (`durationInFrames = durationSec * fps`).
- `durationInFrames` is already audio-driven via `scripts/timing.ts`.
- Captions are computed from `startMs`/`endMs` so they ARE deterministic when
  the timing engine runs. Animations using `interpolate`/`spring` are
  framework-correct in Remotion.

### Phase 7 — Audio pipeline
Current flow: script text → `textPreprocessor.prepareString` → TTS (Fish Speech via
bridge / Piper / Edge TTS / ElevenLabs) → optional `audioPostProcess.applyAudioFX`
→ MP3 saved → caption timing built from the resulting audio duration.

Findings:
- **Compliant with brief:** Piper local engine present, Fish Speech bridge
  present, FFmpeg processing layer present, preview/render share the saved MP3.
- **Conflicts with brief:** `scripts/tts/elevenLabsAdapter.ts` exists and is
  imported by `server.ts` (line 23–35). The task brief explicitly says "Do not
  use ElevenLabs." I did **not** remove this — the project has working code
  paths for it and the brief also says "Do not delete working features."
  Flagged for the user to decide.
- **Raw/processed split:** No explicit `audio/raw` and `audio/processed`
  folders. Audio is written to `public/custom-audio/` after post-processing;
  there is no pre-FX raw copy stored. Adding a raw passthrough would aid
  re-processing without re-TTS, which the brief calls out.

**This is the most fully-implemented part.** `scripts/tts/voicePresets.json`
contains every preset the brief asked for, all in the `ancient_medieval`
category:

Ancient King • Medieval Oracle • Cave Prophet • Dungeon Storyteller • Old Warlock
• Cathedral Monk • Gravel Knight • Shadow Bard • Elder Dragon • Forbidden
Librarian • Royal Seer • Night Watchman • Stone Temple Priest • Wandering Sage
• Dark Cosmos Narrator • Ancient Flamekeeper • Quiet Giant • Mythic Guardian (+ II)
• Raspy Oracle (+ II) • Old Kingdom Narrator.

Each `ancient_medieval` preset carries a `sliders` block with `throatDepth`,
`ancientRasp`, `royalPace`, `chamberSpace` numeric values. `GenerateVoiceOptions`

**Minor issue:** The exported `VoicePreset` TypeScript interface in
`ttsService.ts` (lines 21–37) does **not** declare the `category`, `favorite`,
`tags`, `sliders`, `pacing`, `emotionalIntensity`, etc. fields — even though
they exist in the JSON and are read elsewhere. Anywhere those fields are
accessed today is done via `as any` or untyped lookups. It compiles, but you
lose autocomplete and type safety. Easy targeted fix.

### Phase 9 — Punctuation & cadence
`scripts/tts/textPreprocessor.ts` is excellent. It implements:
- Split into `ttsText` (for the engine) vs `captionText` (for the screen).
- `DEFAULT_PAUSES`, `CINEMATIC_PAUSES`, and `pauseConfigFromRoyalPace(slider)`
  giving commaPauseMs, periodPauseMs, ellipsisPauseMs, lineBreakPauseMs,
  hookPauseMs, endingPauseMs.
- Em-dash / smart-quote / markdown-artifact cleanup, ellipsis collapse,
  whitespace normalization, terminal-period enforcement.
- Royal Pace slider directly drives pause durations.

No changes needed. Matches the brief well.

### Phase 10 — Caption sync
`scripts/timing.ts` is the single source of truth. It:
- Builds captions proportional to word count.
- Enforces a minimum readable display (default 0.8s).
- Forces the last caption to end **exactly** at the audio length
  (`finalCaptionEndDriftSec` < 0.05s by construction).
- Optionally accepts AssemblyAI forced-alignment word timings.

What's missing relative to the brief:
- The output schema uses `startMs` / `endMs`, not `startFrame` / `endFrame`.
  Frame conversion happens later in the renderer. That's fine — but the brief
  asked for a `captionTiming.json` that contains both. Adding fps-derived
  `startFrame`/`endFrame` to the saved JSON is a one-liner improvement.
- No WhisperX / faster-whisper integration yet. AssemblyAI is cloud-only.
- Caption regeneration on audio change: the timing engine recomputes every
  time, so this is implicitly correct.

### Phase 11 — Preview = final render
The frontend `/api/zodiac/voice-preview` endpoint and the final-render path
both consume the same MP3 + timed-captions bundle from `scripts/timing.ts`.
The `meta.json` carries `audioFile`, `captionSyncMethod`, fps, dimensions, etc.
so a preview and render driven by the same `meta.json` should agree.

What's missing: there's no explicit "audio changed but captions are stale" flag
surfaced to the user. The render button is not (visibly to me) disabled until
audio/captions/config converge. A simple fingerprint (sha1 of TTS text +
voice + sliders) stored in `meta.json` and compared at render time would
implement the brief's "warning if audio changed / captions stale" cleanly.

### Phase 12 — Script prompt system

This phase needs **no changes**.

## 4. Bugs / risks discovered

1. **ElevenLabs path is live** even though the brief forbids it. Either
   delete the adapter and routes (risk: breaks any draft using ElevenLabs
   voices) or keep it explicitly off via env (`ELEVENLABS_API_KEY` blank).
   Decision is the user's.

2. **No unified `/api/health` route.** Existing per-engine status endpoints
   would let you compose one in ~30 lines. Risk: low.

3. **No render worker on port 4000.** Brief's home-vs-work-computer split
   is not implemented. Adding it is non-trivial: must factor render code out
   of `server.ts` into a standalone process, define a job queue and progress
   protocol, and add `RENDER_WORKER_URL` to env. Risk: high if rushed.

4. **`VoicePreset` TypeScript interface is missing fields** the JSON actually
   contains (`category`, `favorite`, `tags`, `sliders`, `pacing`,
   `emotionalIntensity`, `energyRating`, `realismRating`, `retentionRating`,
   `contentType`, `exampleLine`). Code that reads them does so untyped.
   Risk: low — purely a typing improvement.

5. **`captionTiming.json` schema lacks `startFrame`/`endFrame`.** Renderer
   recomputes frames from ms each time; persisting them would make the file
   directly consumable by any tool and matches the brief.

6. **`meta.json` is missing `script`, `scriptLines`, `audioRawFile`,
   `audioProcessedFile`, `captionTimingFile`, `fallbackUsed`, `errors`.**
   These can be added at write time without affecting any reader.

7. **No raw-vs-processed audio split.** Audio is written once, post-FX. The
   brief asks for `audio/raw/*.wav` and `audio/processed/*.wav` separately so
   you can re-apply FX without re-running TTS. Useful, non-urgent.

8. **Storage paths hard-coded** to project root rather than env-driven.
   `process.env.STORAGE_ROOT` would make Google-Drive / SSD migration safer.

9. **60 fps render not configurable from UI.** Composition fps is 30. Adding
   a top-level `renderFps` parameter on the render endpoint + composition
   props would let you switch without code edits.

10. **`PROJECT_HANDOFF.md` still describes the project as "YouTube Clip Factory."**
    Mismatched naming may confuse future maintainers. The actual project
    name is "zodiac-program 2.0.0 — Emotional Storytelling Video Engine"
    per `package.json`.
